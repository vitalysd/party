# Рефакторинг — 14–15 октября 2026

## Выполнено

- WebSocket-подписки разделены по соединениям: вкладки не отменяют подписки друг друга. Общая доставка удаляет неисправные соединения и подписки. Обработчик вынесен из main.py в app/api/websocket.py, проверяет формат событий и освобождает соединения через finally.
- Общая политика доступа в app/api/channel_access.py: публичные каналы доступны авторизованным пользователям, личные — только участникам. Проверки применены к списку и карточке каналов, истории, отправке сообщений, реакциям, подпискам WebSocket и событиям печати. Недоступный канал возвращает 404.
- Запрещены ответы на сообщения другого канала. Старые некорректные ссылки скрываются при сериализации истории и реакций.
- Нельзя создать диалог с собой; поиск диалога требует точного совпадения двух участников, а добавление участников убирает повторяющиеся ID.
- Общий запрос загрузки связей сообщения; история выбирает последние записи и возвращает их хронологически. Реакции обновляются из БД после изменения.
- Повреждённый локальный JSON не ломает запуск. Временная ошибка сервера не сбрасывает вход. При смене токена очищаются переписка и подписки, а запоздалые ответы загрузки каналов, пользователей, истории и отправки игнорируются.
- История сохраняет поступившие во время запроса события и неподтверждённые сообщения. Более старый запрос не заменяет новый результат.
- Ошибка отправки сохраняет текст и вложения в локальном сообщении с явным статусом ошибки. Индикатор подтверждения для него скрыт. Сопоставление HTTP-ответа с временным сообщением больше не зависит от совпадения текста.

## Повторный запуск

Frontend: `cd frontend; npm.cmd test; npm.cmd run build`.

Backend: установить `backend/requirements-test.txt` в своё Python-окружение, затем из backend выполнить `python -m unittest discover -s tests -v`. Для уже установленной локальной папки зависимостей в PowerShell задать `$env:PYTHONPATH = "$PWD/.test-deps;$PWD"` из каталога backend.

## Защита голоса и файлов

- LiveKit принимает channel_id и проверяет доступ перед выпуском токена; имя комнаты формируется сервером как channel:<id>. Срок входного токена — 5 минут. Отображаемое имя и identity берутся из авторизованного пользователя.
- Кнопки звонков используют ID личного канала или общий голосовой канал. При выходе из аккаунта соединение закрывается; устаревшие попытки подключения и события старой комнаты не меняют новое состояние. Ошибка микрофона освобождает соединение. Демонстрационные участники и фиктивный таймер убраны.
- События VOICE_STATE проверяют членство и рассылаются только подписчикам канала.
- Вложения сохраняются с записью владельца, канала, имени, MIME и размера. Новые загрузки ограничены 25 МБ и читаются порциями по 1 МБ; частичный файл удаляется при ошибке. Настройки: UPLOAD_DIR, MAX_UPLOAD_BYTES.
- Статическая раздача /uploads удалена. Новые /api/v1/files/<key> и старые /uploads/<key> требуют авторизации. Новые вложения проверяют членство, включая случай отзыва доступа у загрузившего файл пользователя.
- Старые локальные файлы доступны первоначальному загрузившему пользователю, через доступное сообщение или как уже опубликованный аватар. Старые метаданные не переписываются. Для таких файлов проверка ссылок сканирует доступные записи; в дальнейшем их стоит перенести в uploaded_files.
- Приватное вложение нельзя прикрепить к другому каналу или опубликовать как аватар. Аватары загружаются отдельно с purpose=avatar и доступны авторизованным пользователям.
- Прямой S3 presigned-upload API отключён с ответом 410. Он обходил контроль доступа приложения.
- Клиент получает защищённые изображения и файлы с Authorization-заголовком; JWT не включается в URL. Загрузка со сторонних адресов никогда не получает этот заголовок. Object URL изображений освобождаются при смене файла/сессии и размонтировании.

Старые локальные URL поддерживаются авторизованным клиентом; прямые анонимные ссылки перестают открываться.

VPS не менялся. Настройки публичного доступа к уже существующим объектам S3 не проверялись и не изменялись: отключение endpoint выдачи ссылок не закрывает ранее опубликованные объекты. Нужны отдельная инвентаризация, перенос и настройка хранилища. Уже выданные LiveKit-токены и активные подключения не отзываются этим изменением; мгновенное исключение участника потребует вызова LiveKit API удаления участника. ## Повторная отправка и история — 15 октября

- Новый клиент передаёт UUID client_request_id. Сервер атомарно сохраняет сообщение и идентификатор в message_send_requests; уникальный ключ ограничен отправителем. Повтор с тем же содержимым возвращает исходное сообщение без новой записи и повторного WebSocket-события. Изменение текста, вложений, ответа или канала с тем же ключом возвращает 409.
- Обработка конфликта уникальности защищает параллельные запросы. Тест с отдельными соединениями к файловой SQLite-базе принудительно синхронизирует первые чтения, затем проверяет единственную запись и единственную рассылку. PostgreSQL-конкурентность пока отдельно не проверялась.
- Проверка доступа к каналу выполняется и при повторе, поэтому отзыв членства запрещает получение сохранённого ответа.
- Кнопка «Повторить отправку» использует сохранённые текст, вложения, reply_to_id и client_request_id. Одновременный второй клик не создаёт дополнительный запрос. HTTP-запрос имеет тайм-аут 20 секунд.
- HTTP, WebSocket и загрузка истории сопоставляют временное сообщение с подтверждённым по отправителю и client_request_id. Два одинаковых текста остаются двумя независимыми сообщениями. Потеря HTTP-ответа после WebSocket-подтверждения не возвращает статус ошибки.
- before_id указывает на сообщение в том же канале; сервер получает его timestamp и использует условие по паре (created_at, id). Старый параметр before сохранён для совместимости. Тест проходит всю историю страницами по 3 записи, включая 7 сообщений с одинаковой микросекундной меткой.
- В обычном, мобильном и личном чате появилась загрузка предыдущей страницы с отображением ошибки и повтором. Страницы объединяются без удаления новых событий; двойная загрузка блокируется. Сортировка сохраняет микросекунды PostgreSQL. Добавление старых записей не запускает автопрокрутку к последнему сообщению.
- В этой итерации проходят 22 backend-теста и 18 frontend-тестов. Production-сборка проходит. Внешние сервисы и VPS не изменялись.

Для нового протокола повтора backend должен быть обновлён до клиента: прежняя версия сервера игнорирует неизвестный client_request_id и не гарантирует отсутствие дублей. Запросы старых клиентов без ключа сервер принимает, но идемпотентность на них не распространяется. Таблица message_send_requests создаётся текущим startup create_all без изменения существующих столбцов messages.
